# Seller Flex 批量库存助手 v0.7.3

Pack 原生完整订单导出 → ERP 自动分拣 → ERP 通过 Amazon SP API 获取标签并合成固定「上欧代、下 SKU」版式。标签仅在 ERP 缓存，不在电脑缓存。保留原库存功能，不改变自动补库的暂停/启用状态。本目录更新不代表配套接口已部署、浏览器已安装或真实业务验收已完成。

Receive 手动选择或拖入 CSV 后，助手先校验整份文件。超过 3,000 条库存记录时自动拆成多份，每份带表头，按顺序提交并分别确认结果。同一原文件再次加入时，助手会核对原文件及各分段的提交记录。真实试跑与手动队列共用页面锁，试跑期间禁用手动提交按钮。

## Pack 订单同步

1. 保持原扩展 ID 升级并重新加载，刷新 Seller Flex Pack 页面。复用现有 A1C5 ERP 设备连接。
2. 全量导出：选择日期、Shipout Time 和 Ready to pack/Packed 页签，清空订单搜索，点击「展开全部并导出到 ERP」。插件连续点击 `Load More`，等全部加载完成后全选，核对页签总数及原生 Order List 明细，然后自动同步，无需再次点击弹窗按钮。范围仅为当前日期、时段和页签；不会切换筛选项。加载期间可点击「取消展开」。
3. 指定订单：仍可自行勾选，点击「导出当前所选订单到 ERP」打开 `Order List`，再点击「同步到 ERP 并分拣」。两种入口均触发原生 `Download order list`，先在扩展 IndexedDB 保存完整 XLSX 与稳定请求 ID，再上传 ERP。按 Transfer Id + SKU + FNSKU 去重；同身份数量改变由 ERP 标记待核对。
4. ERP 确认新增行后，通过 Amazon SP API 获取官方标签，按数量合成固定「上欧代、下 SKU」分组标签。重复行和待核对行不生成打印标签。插件不调用 Seller Flex 的行标签 Download、Print 或批量 PDF，不采集、上传或缓存 PDF，也不执行 Pack 或 Ship。
5. 订单、分拣表、带图备货单及分组标签在 ERP 订单分拣页的 Pack 批次中查看。主图和 API 标签仅在 ERP 缓存。未就绪时显示 ERP 待生成状态，现有后台轮询自动重试，无需保持原订单弹窗。旧 ERP 若未返回 Amazon API 标签来源，插件明确提示升级 ERP，不回退到 Seller Flex 标签导出。

全量导出必须持续点击至 Load More 消失，再核对页签总数和稳定的完整订单明细；即使达到页签显示数量，或某一轮没有新增行，也继续点击恢复可用的 Load More。连续 2 分钟没有进展或总过程超过 10 分钟则报错停止，不把超时当作完成。筛选或数量变化、无法全选、Order List 明细不一致时也停止，不上传不完整列表。单次最多 10,000 条商品明细，文件仍受 12 MB 上限约束。再次导出相同订单继续使用 ERP 去重规则，不重复备货或打印。不会点击 Pack 或 Ship。

断网或后台重启时，已保存原始 XLSX 自动原样重试；保留稳定请求 ID 防止重复导入。页面或数量变化会停止订单采集。切换设备/店铺或断开连接后，旧 XLSX 冻结在原身份下，不会使用新身份上传。升级后历史队列中的 Seller Flex PDF 会作为过期数据清除，不上传、不复用；原始 XLSX 仍保留。不要卸载扩展或清理扩展站点数据，以免浏览器删除本机待传订单。

同步前或同步期间若另外点击原生 Download/Print，会停止订单采集并提示刷新 Pack 页面，再打开相同订单列表继续。其他下载仍正常执行；刷新用于清除旧导出请求，不靠等待秒数猜测它是否已结束。普通同步无需此额外步骤，已上传或本机保存的订单进度保留。

原生订单下载已触发但尚未成功捕获时，超时、取消或弹窗变化也会要求刷新后继续，防止迟到的旧 XLSX 混入新订单。文件已成功捕获后的网络重试无需刷新。

捕获器只接受 Pack 路径单次 30 秒窗口中的原始订单 XLSX，要求原生文件名、MIME、文件头和大小匹配，拒绝 PDF 捕获请求；每个文件上限 12,000,000 字节，超限明确提示减少所选订单。只接收本次随机 nonce 的响应。支持新 Blob 及实测原生 `data:` base64 下载（含 FileSaver 的脱离 DOM 的 anchor click/dispatchEvent）。`data:` 只读取当前下载链接内嵌内容，先限制长度，再严格核验 MIME、base64 编码及文件头；不请求 URL，不接受 HTTP、JavaScript 或其他类型。设备令牌仅在后台使用。未增加 downloads、scripting、cookies 或 tabs 权限。

## 自动补库

- 由 ERP 每小时巡检全量 JIT/J1T。启用时从下一次新开始的巡检生成自动任务。首次处理最近 7 天新增且无订单的商品，排除禁售和 suppressed 商品。按实时 API 可售库存计算，已出单及 A/B 组新品补到 5 件，C 组、集美组和未归组新品补到 2 件。未出单老商品无需补库。
- 空闲时先领取人工两行试跑，再领取 `/automatic/claim` 自动批次；已有任务继续使用自己的协议。旧试跑 `ACKNOWLEDGED` 可转入自动任务，旧试跑 `UNKNOWN` 保持只读核对。
- 自动批次只允许 A1C5、GOOD、每行 1–5 件、每份最多 2,900 行。新版插件按批量协议领取；ERP 分组复核实时库存和商品状态，保存进度后才发放一份 CSV。复核中断可继续，发放过许可的文件只能核对回执。空批 `SKIPPED` 不上传。
- 唯一 CSV 许可、双重 SHA-256 校验、共享 Web Lock、手动队列保护和页面检查与试跑一致。一次只执行一批，完成回执确认后约 5 秒继续，空闲或错误时约 60 秒再检查。
- 自动 `COMPLETED`、`FAILED` 或 `UNKNOWN` 必须收到匹配任务、租约和事件 ID 的 `RECORDED/submitted:true` 持久化证明，才释放本地批次锁；UNKNOWN 不等于补库成功，对应 SKU 仍由 ERP 锁住，直到实时 API 达到本次提交时的目标库存（2 或 5）或管理员核对。其他 SKU 的后续批次可以继续。
- 回执丢失时原样重放同一事件。重启后也可通过 `/automatic/claim` 返回的精确 `previousJob` 持久化证明恢复；普通错误、错 ID、错租约、错事件不释放锁。普通批次只保存最近回执及各标签页待清理文件证明，不占用完整交接归档。
- 只有服务端已持久化回执，且本标签页自有文件的文件名、字节数、修改时间和 SHA-256 全部匹配，才清空上传控件；同标签页刷新后仍可用持久化证明清理。不会仅凭同名删除用户选择的文件。每个标签页只保留一份清理证明，最多 32 个待清理标签页；达到上限时新标签页停止发放许可，已有证据保留。

## 真实小批试跑

- ERP 服务端独立决定是否开放任务；配对及原模拟心跳协议仍为 `SIMULATION`。打开 A1C5 的 Receive 页后，内容脚本空闲时先通过后台请求 `/live/claim`，不自行创建任务。
- 只接受 `REAL_TRIAL`、A1C5、最多两行、GOOD、每行 1–5 件。`/live/prepare` 必须先完成服务器实时 API/映射校验，再提供新生成的规范 UTF-8 CSV。后台验证业务行与 CSV 的 SHA-256 一致。
- 后台先原子保存 `PREPARING`，再请求清单；先保存 `DISPATCHING`，再向唯一标签页发放一次 CSV。断网、刷新、后台重启或页面失联后只按稳定文件名核对，绝不重新生成上传许可。多个标签页共用 Web Lock，后台也串行处理许可。
- 未提交过期换领：本地仍为 `CLAIMED` 或 `PREPARING`，且服务端对同一旧任务 ID、租约 ID 明确返回 `EXPIRED` 或 `SKIPPED`，并带有 `submitted:false` 的已落库证明时，保留该证明并允许领取新任务。没有证明、证明不匹配、已进入 `DISPATCHING` / `DISPATCHED` / `UNKNOWN` 时均不解除上传锁；本地时间到期本身不作为安全换领依据。这也覆盖服务端预检取消任务但响应丢失的恢复。
- 仅在当前路径 `/receive`、仓库标识严格等于 A1C5、无可见弹窗、无手动队列且上传控件未选文件时上传。文件名使用服务端 `receive-<任务ID>.csv`，不追加随机后缀；通过原生 file input 的 `change` 事件执行一次上传。不自动操作 REMOVE。
- 结果按状态表中的完整文件名匹配，支持页面的重复表头和 `ErrorsRefresh` 表头。仅唯一行 `Completed` 且错误数为 0 才回传完成。明确 `Failed` 回传失败；部分错误、重复记录、无法识别错误数、页面切换及 4 分钟超时均回传 UNKNOWN，不猜测成功 SKU。
- 原始行文本、错误数、观察时间随回执保存，发送失败后以同一事件 ID 原样重放。Amazon 当前错误下载控件没有可验证的 CSV 接口，因此此版不自动下载错误报告，也不按位置推断失败 SKU；部分成功留待核对。UNKNOWN 可继续只读核对并回传后续明确结果。
- ERP 管理员明确交接后，旧设备凭同一任务与旧租约的 `TRANSFERRED` 证明归档整个旧 `live`（包括待确认回执、上次回执和页面所有者）、原设备身份和证明，再释放旧租约。即使旧回执返回 409，也继续请求此证明；其他失败不丢弃证据。归档 `archivedLive` 最多 10 份，满时停止，不覆盖。
- 已发放 CSV 或提交中的任务交接后只能核对结果，不能取得第二份上传许可。未发放 CSV 且已被服务端证明未提交的任务，可以在交接回来后接受同任务的新租约。旧页面的旧租约命令会被拒绝；`ACKNOWLEDGED` 等待 API 确认阶段仍检查交接证明。
- 未完成真实任务禁止普通重新配对或断开。只有凭据已被 ERP 拒绝时，用户才可明确选择保留完整执行记录和旧身份后解除配对；旧记录不以新身份重放。

## 正式连接

1. Edge 打开 `edge://extensions`，开启开发人员模式，加载此文件夹（含 `manifest.json`）。升级请在原扩展位置更新并重新加载，保留扩展 ID；不要卸载后重装，以免浏览器清除本地证据。v0.3 的 `sf-erp-v2` 存储键及原手动记录均继续使用。
2. 在同一个浏览器配置文件中打开 `https://htcerp.app/settings?tab=inventory`，以管理员登录。扩展弹窗自动检测登录，只读检查不会授权或连接。
3. 输入设备名称，点击「一键连接当前 ERP」。无 ERP 标签页时点击「打开 ERP / 登录」；旧页面没有新版连接脚本时，保存表单后手动刷新，或打开新标签页。扩展不会刷新您的页面。
4. 确认弹窗的卖家、站点和仓库范围。连接只登记设备，执行设备的选择与交接在 ERP 库存页完成；新连接不会自动接管现有任务。
5. 无法使用当前登录时，展开「使用配对码连接」，输入 ERP 生成的一次性配对码。配对码不保存；本地隔离测试仍使用此入口。
6. 后台每分钟心跳并检查模拟任务；也可点击「立即检查」。模拟只计算规范 CSV 的 SHA-256 与行数，`PASSED/SIMULATION` 不等于 Amazon 已上传。

授权请求使用固定同源登录会话接口。后台先保存随机证明，再把 SHA-256 挑战发送给 ERP 标签页；证明及设备令牌不进入网页、内容脚本或弹窗。两分钟有效期内，同请求 ID 和证明可恢复回复丢失及后台重启。恢复时重新检查管理员、范围和原始 cookie 会话；失效授权不会复用。已有设备、未确认回执或真实执行记录不会被一键连接覆盖。

浏览器关闭或系统休眠时不轮询，唤醒后恢复；Chrome/Edge 闹钟可能延迟。连接错误保留待确认回执，下次心跳正常时原样重传，服务端按 jobId/nonce 幂等确认。一般断网且回执未确认时禁止重新配对或断开，以免遗失回执。没有待确认回执时，「断开本机连接」清除本地 ERP 凭据；服务端撤销设备需在 ERP 完成。

如旧设备被撤销，ERP 返回 401/403，弹窗会出现「保留回执并解除旧配对」。由用户明确点击后，扩展在同一次存储写入中将未确认模拟回执、完整真实执行记录及原设备 ID、地址、范围、时间保留到独立的 `archivedReceipts` 列表，同时清除旧凭据，然后才能重新配对。归档不代表上传成功或服务端确认；旧回执永不随新身份重传。归档跨扩展重启、重新配对及普通断开保留，不包含旧令牌。最多保留 10 份，达到上限时停止恢复并提示管理员备份核对，绝不自动覆盖证据。

## 明确边界

- 模拟通道接受每次最多 3,000 行。独立真实通道接受最多两行 REAL_TRIAL 或最多 2,900 行 AUTO_REPLENISH。真实库存任务使用 GOOD，每行数量 1–5。
- 后台连接器不直接访问 Seller Flex DOM；受限内容脚本负责一次上传及结果核对，不调用未验证的 Amazon 私有接口。
- 原手动上传助手仍由用户选择文件并点击按钮触发；与 ERP 模拟通道独立。
- 原 ZIP 只有接收入库/调整页和上传结果表适配，没有可验证的库存数量 DOM 适配。本扩展不读取实时库存或扫描全仓；库存权威数据由 ERP 的实时 API 提供。
- 凭据仅存扩展 `chrome.storage.local`，启动时设 `TRUSTED_CONTEXTS`；不会回传弹窗、内容脚本或网页。手动记录代理限制 `sf-inventory-v1:`；真实消息只接受本扩展、顶层 `/receive` 文档且具有文档 ID 的发送方。服务端错误正文与原始网络异常不展示。
- 生产权限仅 `storage`、`alarms`、`https://htcerp.app/*` 、ERP 顶层受限中继及原有 Seller Flex 内容脚本匹配；使用现有 ERP 主机权限查询标签页，不申请 cookies、tabs、scripting、webRequest、downloads 或所有站点权限。
