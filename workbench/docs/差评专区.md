# 商品差评专区

入口：`https://htcerp.app/feedback`。本模块是 ERP 内的美国站自家商品周报，使用已有 Amazon SP-API 凭据和已保存的 Seller ID。

## 数据与流程

每周一北京时间 09:00 生成汇总，可在页面手动生成。首次全量扫描先读取本店刊登，再按 ASIN 去重读取 Customer Feedback 的负面主题。店铺约 7.7 万条刊登，首次运行可能持续数小时甚至数日；页面在运行时每 15 秒刷新进度，完成后停止轮询。

每条商品显示主图、关联 SKU、ASIN、Amazon 原始统计区间、负面主题、提及次数、主题占比、评分影响、代表性摘录及核查建议。无反馈不等于没有差评；失败、父体排除和关系待核对均单独展示。主题是统计区间内的汇总，不能视作本周新增差评，也不能将两种排序的提及次数相加。没有负面主题时跳过重复的评分影响排序请求。

刊登超过 Amazon 1,000 条分页范围时按创建时间拆窗；边界重叠并按 SKU 去重。无法核齐的时间窗会标注为部分完成。父体及关系不明的刊登不会强行分配到子体。图片优先读取刊登主图，再通过 Catalog Items 补充。

配置复用现有 RUNNER，生产 Workflow 步数上限 25,000，Jobs 子请求上限 1,000,000，支持当前大店铺分批运行。每批最多 20 个 ASIN，不把全店响应保存在 Workflow 内存。调度每周幂等，正在执行时重复生成会返回同一任务。超过七天仍在运行的记录可被新任务接替；旧任务的写入由其 run ID 隔离。

## 运营归属

管理员在商品卡片展开“分配负责运营”，为各 SKU 选择 ERP 中启用的运营或管理员账号。归属键是店铺、站点和 SKU，后续周报复用。同一 ASIN 对应多个 SKU 时共享差评主题，但可分属不同运营；发给每位运营的消息只列出他负责的 SKU。

可筛选全部运营、我负责的、待分配或指定运营。停用或降为只读的账号不会继续作为有效负责人。处理状态和备注以店铺、站点、ASIN、主题为键持续保留，写入独立历史记录。

用户尚未提供运营名字的原始来源和识别规则。当前支持人工维护归属，待规则明确后接自动匹配，不猜测 SKU 中的员工标识。

## 企业微信

管理员展开“运营与企业微信设置”：

1. 配置自建应用 Corp ID、数字 Agent ID、应用 Secret。使用 ERP 现有 AES-GCM 凭据库，保存后不回显。
2. 绑定 ERP 账号和企业微信通讯录成员 UserID。只允许单人成员，不接受 `@all` 或多人列表。
3. 验证应用连接；核对应用可见范围及企业微信要求的可信 IP。获取 token 成功仅证明应用凭据可用，成员实际送达需要真实通知验证。
4. 预览“企业微信草稿”，确认按运营分组的内容，点击“发送给已绑定运营”。未分配商品、未绑定成员的运营不会收到消息。
5. 开启“周报完成后自动通知负责运营”，之后完成的周报会自动通知。

发送记录以周报及运营为唯一键。已发送不重复发送；明确失败可在发送记录中重试；超过十分钟被中断的准备阶段可重新取得发送租约。旧执行必须通过租约校验才能进入发送。发送阶段中断、超时或无法解析的结果标为“结果待核实”，不会自动或通过失败重试再次发送。通知长文本按 UTF-8 字节截断并附完整周报链接。

自动汇总和自动通知均有独立开关，迁移默认关闭。首次生产发布可按已授权的每周汇总需求启用汇总；企业微信通知应在应用与成员实际配置后启用。

## 验证

新增 Vitest 覆盖北京时间周边界、主题去重、刊登关系、ASIN 去重采集、失败隔离、分页缺口、调度幂等、操作权限、成员限制、凭据加密、运营分组和消息去重。workerd 运行时测试从真实 Hono 路由启动模拟周报，验证 Workflow、D1、图片和原始统计指标。Playwright 覆盖专区浏览、备注保存、运营分配、成员绑定、模拟发送和 360–2560 像素布局。

真实企业微信凭据和成员尚待管理员配置，测试没有向真实成员发送消息。仓库全量格式检查仍有既有标题检测等文件的格式/换行问题；本模块新增文件的格式检查单独通过。
