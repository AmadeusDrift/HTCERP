# 订单分拣迁移交接

入口：https://htcerp.app/order-sorting

本阶段已发布 ERP 分拣迁移。后续 SellerFlex Pack 批量导出 OrderList → 插件传输完整订单 → ERP 分拣 → SKU 标签链路尚未接入，本阶段以手动上传原始 Order List 为入口。

## 已上线

- 原脚本的分类优先级、精确 SKU/产品代码匹配、关键词、未知分类、SKU+FNSKU 汇总和原始订单保留。
- 上传预览后生成分组工作簿，支持逐个下载和 ZIP 下载。输出包含“订单明细”“亚马逊订单”，保留样表格式、合并单元格和金额公式。
- 产品属性 A–K 在 ERP 维护，管理员导入、编辑、导出；运营生成分拣，查看角色只读下载。生成时自动补录新增代码及可唯一确定的空分类。
- 同名文件只有内容一致才可再次生成；包括模板保留内容的语义比较，不因样式变化误拦。
- 版本冲突及同名冲突整批回滚；请求 ID 可安全重试；历史结果保存原配置与模板，支持游标加载更早记录。
- 更换模板不会再次导入上次选择的旧属性文件。缩短输出时清除模板旧订单尾行。

## 验证

- 真实样例 2 份 × 模板 2 份，对比原 Python 脚本：10 个工作簿、9,756 单元格的值、公式、尺寸、合并、筛选和有效样式一致。仅空 diagonal XML 标签的序列化有无不同，均无实际边框。
- 完整测试 53 文件、442 项通过；TypeScript、生产构建、Worker 打包和新增文件样式检查通过。
- 浏览器本地隔离联调通过：首次导入、编辑 ERP 属性、仅更换模板、预览、保存、下载并重新读取工作簿、刷新后历史下载。
- 额外覆盖：并发版本回滚、同一请求重放、同名差异冲突、样式变化不误拦、34 批相同时间戳历史翻页。
- Workers 服务端使用 ExcelJS 原生文档入口，并通过 `worker-streams.cjs` 将 readable-stream 映射到 node:stream，解决浏览器打包版本第二次请求挂起及原生入口旧流库的 XML 调试输出。连续导入在完整 Worker 联调中验证通过。
- 线上页面 HTTP 200 且含新路由；未登录清单、历史和工作簿接口均 HTTP 401。生产库核验配置、文件哈希、空记录及补库暂停状态一致。
