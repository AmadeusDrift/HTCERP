# Pack 订单导出与 ERP 分拣（v0.6.2）

本记录取代 v0.6.1 的 Flex 原生标签方案。用户已明确纠正：订单表来自 SellerFlex，商品标签来自 Amazon SP-API；所有分组固定欧代标在上、SKU 条码在下。标签缓存只保存在 ERP，不保存在用户电脑。

## 当前流程

1. 在 A1C5 Pack 勾选订单，点击「导出当前所选订单到 ERP」，再点击「同步到 ERP 并分拣」。插件只捕获完整原生 XLSX。
2. 原始订单存档到 ERP，按照现有产品属性和脚本分组。店铺/站点/仓库内用 Transfer Id + SKU + FNSKU 去重；相同数量跳过，数量变化单列待核对，不重复生成备货量。
3. ERP 按服务端确认的 SKU/FNSKU 获取标签。首次使用 Amazon createMarketplaceItemLabels 请求一张 70×30 mm 原标，核对 FNSKU、页数、尺寸后存入私有缓存。每批最多 100 个不同 FNSKU；相同 FNSKU 的不同 SKU 分开请求。
4. 后续批次直接复用 ERP 原标，按件数生成一件一页 80×80 mm 合成标签：固定欧代标在上、对应 SKU 条码在下。原始条码不重画。
5. 合成 PDF 也持久存入 ERP。重复下载直接返回已保存的相同字节。模板变化仅使合成结果失效；匹配的原始 SKU 标签继续复用。
6. ERP「订单分拣 → Pack 自动分拣」下载分组表、分组标签或完整 ZIP。旧批次通过「生成／重试标签」更新标签，原订单和去重账本不重复写入。

## 缓存和恢复

- 原标缓存范围包括店铺、站点、区域、语言、SKU、FNSKU、标签尺寸。合成缓存还包括完整有序行、件数和固定模板 SHA-256。
- 原标与合成文件均在私有 R2；D1 表 product_label_cache 使用可续租、带持有者校验的锁协调不同电脑与 Worker。损坏缓存不会作为正确结果使用。
- 分组文件使用内容哈希校验；列表用 R2 HEAD 的大小与 ETag 判断状态，不读取全部历史 PDF。下载时完整校验 SHA-256。
- v0.6.2 清除插件旧版待传 Flex PDF，不再采集、上传、缓存 Flex 标签。原始订单 XLSX 的离线待传机制保留。
- 标签生成时插件接口立即返回响应头与 JSON 空白，生成完成再返回最终 JSON，避免 MV3 的首次响应限制；Pack 请求截止时间 180 秒，其他库存请求时限不变。
- 单分组最多 5,000 张、32 MiB 合成 PDF；超过数量在订单去重入账前拒绝，提示减少选择。内部每 1,000 张分段合成，保留顺序和总数。
- 自动补库继续暂停（enabled=0），本次没有执行 Pack、Ship 或库存写入。
