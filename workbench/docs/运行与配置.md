# 工作台运行与配置

## 本机打开

要求 Node.js 24、pnpm 11.25、Python 3。进入本文件上两级的 `workbench` 目录后执行。

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm db:local
pnpm dev
```

浏览器访问 http://127.0.0.1:8787 。所有 HTTP 查询由同源 API 处理。初始化会先应用 SQL 迁移，再从既有探测响应还原商品和观测。第二次运行前先关闭开发服务，以免同时写本地 SQLite。种子脚本仅用于开发和部署初始化，页面没有导入入口。修改前端后重新构建，修改 Worker 源码后开发服务自动重载。按 Ctrl+C 结束前台服务。

本机开发命令只监听回环地址，并显式注入本地管理员身份。工作区上一级的 `.env` 不作为开发服务配置。实际云端 API 默认拒绝未认证请求，角色通过验证后的 Access 身份映射。

## 数据口径

样本来自美国站既有查询的返回范围。Temu 累计销量读取 `sold`，其余采集平台读取 `totalSold`。平台累计、日、周、月分别保存。筛选价格基于美国站 USD 最低展示价，需在复核时确认规格。样本的供应商更新时间与请求时间分列。缺失的请求时间保持为空。历史来源按证据和日期记录，同一日可能有多份证据。

本地目录含 22,664 件商品，其中 Temu 16,272、SHEIN 3,185、TikTok Shop 1,595、AliExpress 1,612。例示的 Temu 家居根类目 `9711` 和最低展示价 ≤4 美元在三个半开销量层中分别命中 55、41、88 件。此计数是历史缓存样本的复核结果，线上每日任务按策略、翻页上限和来源能力单独记录覆盖。

## 云端准备

开发环境使用 Wrangler 本机持久化。预发布与生产各准备独立 D1、R2、Workflow、API/Jobs Worker、Access 应用和域名。仓库内的两个 Wrangler 模板共用本地测试 UUID。云资源由账号管理员准备，先在预发布核对每项配置与费用授权。以下命令仅在切换对应环境时执行。

1. 为预发布准备 D1 与私有 R2。按该环境实际值生成独立部署配置。生成器只写本地忽略的配置文件，相同文件已存在时停止，以保留手工设置。

   ```powershell
   node scripts/cloud-config.mjs staging <D1-UUID> <D1名称> <R2名称> <工作台域名>
   ```

2. 可直接填写 `<Worker 名称>.<账号子域>.workers.dev` 使用 Cloudflare 自带的网址。Cloudflare Zero Trust 的自托管应用保护该域名下的 `/api/auth/setup`，仅放行所有者邮箱。API Worker 添加 `ACCESS_TEAM_DOMAIN`（如 `team.cloudflareaccess.com`）、`ACCESS_AUD` 和 secret `APP_ROLES`（例如 `{"owner@example.com":"admin"}`）。所有者首次在该路径验证邮箱并创建管理员用户名和密码。之后成员访问 `/login`，用管理员分配的用户名和密码登录。工作台业务接口逐次检查会话和账号权限。Jobs Worker 无公共访问域名。

3. 在有部署授权的环境执行 `pnpm build`，用生成的配置检查预发布 Worker，并按下列顺序迁移和部署。部署前在控制台为各 Worker 建立 secrets，或用 `wrangler secret put 名称 -c 对应配置文件` 交互输入。避免把值放进命令行或以 `VITE_` 命名。

   ```powershell
   pnpm exec wrangler d1 migrations apply DB --remote -c wrangler.jobs.staging.local.jsonc
   pnpm exec wrangler deploy -c wrangler.jobs.staging.local.jsonc
   pnpm exec wrangler deploy -c wrangler.api.staging.local.jsonc
   ```

   首次需要云端样本时，先运行 `python scripts/bootstrap.py --output .local/bootstrap.sql`，再用相同 D1 配置执行 `wrangler d1 execute DB --remote --file .local/bootstrap.sql`。种子 SQL 包含私有业务数据，只存入数据库。原始历史证据的缓存文件应按引用放入私有归档或保留受控的原目录。云端运行的新来源响应由 Jobs 归档到 R2。

4. **数据连接**。管理员在「数据与模型设置 → 数据连接」点「配置连接」，可分别填写极鲸云的 App Key 和 App Secret、OpenRouter 的 API Key，或 Amazon SP-API 的 Client ID、Client Secret 和 Refresh Token。极鲸云支持五组独立配置。选择第 1 至第 5 组之一，填入配对的 App Key 和 App Secret 并保存。可以只填一组，更新时只替换所选组。保存后页面只显示绑定状态。保存不会发起供应商调用，在线采集和 AI 研究仍由各自预算控制。

   自建环境先应用数据库迁移，将同一个随机 32 字节密钥（64 位十六进制文本）作为 `CONNECTIONS_KEY` secret 绑定到 API 和 Jobs Worker。工作台用它加密保存在 D1 的连接凭据。保留这项绑定供后续版本使用，更换加密密钥需要先迁移已有密文。本机预览会为对应数据库单独生成加密密钥，文件保存在当前用户的本地应用数据目录。已有的部署仍可使用 Worker 上绑定的供应商凭据。

5. **Amazon 美国站**。保存凭据后，管理员可以点「测试连接」发起 LWA 授权和一次美国站目录读取。验证后在商品详情输入关键词或 ASIN，首屏显示至多 6 个目录结果。确认匹配时按 ASIN 查询常规美国站新品报价。价格、运费和可用的类目排名分列展示。Amazon Haul 共用这组 SP-API 凭据。

6. **生产启用**。预发布配置初始不注册 Cron。生产配置保留每 30 分钟和每 5 分钟的触发器，由 Jobs 根据对应功能的设置执行。需要按分钟检查每日任务时，在该环境 Jobs 配置的 `triggers.crons` 另加 `* * * * *` 并重新部署，再在设置页指定北京时间、启用调度及设置预算。已有域名需要更换时，将新域名绑定到同一 API Worker，更新 Access 的首次开户保护路径，保留 D1、R2 和 Workflow 绑定即可。成员在新网址重新登录。

## 工程取舍

本项目以官方 Wrangler 原生配置装配两个 Worker。已有 VibeStart 0.1.3 dry-run 的 Workers 组合依赖预览 Void 且没有 D1 选项。本机全局 CLI 为 0.1.2。本次手工建立 pnpm 工程和 React 组件，没有生成 VibeStart 管辖文件。生产数据库使用 D1；Node 内建 SQLite 仅用于开发种子与离线校验。包的确切版本见 `pnpm-lock.yaml`。

外部接口依据 [Cloudflare Wrangler 配置](https://developers.cloudflare.com/workers/wrangler/configuration/)、[Amazon LWA 鉴权](https://developer-docs.amazon/sp-api/docs/connecting-to-the-selling-partner-api)、[美国站目录查询](https://developer-docs.amazon/sp-api/reference/searchcatalogitems) 和 [ASIN 报价](https://developer-docs.amazon/sp-api/reference/getitemoffers) 实现。实际权限和字段覆盖须由已授权账号验证。


## 调度、预算和复核

设置页发布新版本时，运行中的任务继续引用原版本。后台按北京时间判断是否到达管理员配置的执行时刻，当天重复触发复用已有轮次。所有密钥组共用团队每日数据预算。按组号优先使用已绑定的密钥；遇到明确的余额不足响应后，同一业务日跳过该组，重新保存凭据后可再用。未提供扣费回执时保留本次预留，剩余预算够用才尝试下一组。鉴权失败、限流和网络中断不会自动换组。多个 Key 属于同一供应商余额账户时，可用积分仍由该账户决定。每轮配置翻页上限、重点更新数量与自动研究上限（0–3 件）。当真实来源仅支持站点、关键词或指定类目时，任务页会分别展示上游参数、本地价格及累计销量过滤和本次停止原因。

自动研究先看本轮实际达标、销量层级最高且尚未研究的商品。同一策略版本下，未变化的商品业务快照可以复用原研究。改变研究范围或数据发生变化后产生新的证据链。每个在线步骤发送前原子预留费用，成功步骤可重放已经归档的证据。超时或无法核实费用时保留预留，已确认扣费的限流或上游服务错误支持在等待期后手动补跑。费用不确定时需先在供应商账单核对，当前版本无自动对账。

极鲸云按每次 10 积分预留，模型调用分别按 Decisions 0.003 美元、Terra 0.03 美元预留。它们是程序的调用准入值，实际金额以返回的 usage 与供应商账单为准。生产开启前核对账号定价、模型可用性及供应商侧额度。每轮 AI 上限为 0 时仅生成本轮待研究清单。观察或补证分流不再调用 Terra。手动研究可附最长边 512 像素的私有参考图，配合人工选择的来源商品及可取得的规格、历史和已确认 Amazon 对照使用。

本机服务可通过另一终端在同一目录执行 pnpm stop 关闭。全流程测试使用独立库。前端及双 Worker 通过本地构建，在线权限、真实计费、实际 Amazon 字段和部署后的每日触发应在配置对应账号后核验。

## 核对连接与实测字段

管理员在「数据与模型设置 → 数据连接」可以逐组验证极鲸云签名，免费读取美国站点列表。当日同一凭据复用验证回执。已记积分、待核积分按北京时间统计所有槽位的工作台调用，供应商的余额以其控制台为准。打开商品详情或已保存的评论报告不触发来源查询；更新付费评论样本、后台采集和任务内详情更新共享团队预算。明确的余额拒绝会跳至下一组，超时和鉴权失败会停止。迁移 0015 保留旧账，并将直接查询纳入同一张预留表。

Amazon 卡片的「核对订单字段」抽查最近七天的一页美国订单。「查询已刊登商品记录」需要本店 Seller ID，只查看最多五条已有刊登的 SKU、创建日期和变体关系。两个按钮均只显示样本覆盖情况。详情页的目录对照和评论主题有各自的权限与覆盖范围。
