# HTCERP AI Agent / Super Agent 分阶段实施方案

日期：2026-11-01（北京时间）  
状态：第一、第二阶段已上线；第三、第四阶段已通过工程验收，准备发布。用户已授权推进至第四阶段，验收后 push 和上线；第五阶段未开始。
适用项目：HTCERP 自动选品工作台。

## 1. 我们要做什么

把现有运营助手做成工作台里的选品研究员。

用户交给它一个目标，它自己选择工作台已有接口查资料、比较结果、发现缺口、继续调查，最后回到原对话交报告。用户可以查看进度、补充条件、暂停或停止。

例如：

> 按当前条件看看这批厨房收纳商品，挑出最值得继续研究的三款。先看已有资料，需要在线补查时告诉我范围和额度，最后解释推荐和淘汰的原因。

成功的标准是任务完成和结论有据可查。能够聊天、能够生成计划、能够启动后台任务，都只是其中一部分。

## 2. 已经决定的方向

- 在现有项目上逐步开发，保留 Workers、D1、Workflows、R2、登录、权限、队列和费用账本。
- 不替换当前模型接入；不因使用 DeepSeek 的设计而改用 DeepSeek 模型。
- 参考 DeepSeek Harness 和 dsh-superagent-prototype 的设计，当前不引入其运行时或插件依赖。
- 分清对话接待、调查任务和接口执行三个职责；首版使用一个调查执行器，不启动多 Agent 协作。
- 先完成已有资料的调查，再开放授权后的在线补查。
- 已有权限、预算和业务规则由服务端执行，提示词不能替代它们。
- 本文建立阶段边界。开发按阶段执行、按阶段验收，不把整份路线图视为部署或付费调用授权。

工程人员执行时使用配套的[工程执行清单](../../docs/superpowers/plans/2026-11-01-htcerp-super-agent.md)。

## 3. 当前已经有什么

以下以 2026-11-01 调查时的本地实现为依据，不把旧需求文档中的设想当成已完成能力。

| 能力 | 当前情况 | 本方案的处理 |
| --- | --- | --- |
| 个人多轮对话、图片、历史记录 | 已有 | 保留并扩展调查进度展示 |
| 助手工具 | 查库、看自己的任务、准备选品计划三个 | 扩展工具，不重新接供应商 API |
| 商品列表 | 已有分页、多条件筛选、排序 | 与助手共用查询规则 |
| 商品详情 | 已有历史、SKU、快照和人工反馈 | 接成读取工具 |
| 评论、Amazon 竞品及报价 | 有已保存结果和部分在线调用入口 | 先读已有结果，再接在线更新 |
| 后台研究 | 已有证据分流、Amazon 对照、机会报告、复核 | 作为调查中可以调用的业务任务 |
| 执行基础 | 已有权限、队列、预算预留、限速和证据归档 | 继续复用，补整次调查的关联和总额度 |
| 助手连续执行 | 最多两次模型请求，第二次不能重复同名工具 | 改为有步数、预算和时间上限的调查循环 |
| 任务交付 | 助手能给任务链接，不能自动回收研究结果继续工作 | 接通结果回收和原对话报告 |

关键代码入口：

- [助手工具](../packages/assistant/agent.ts)、[对话接口](../packages/assistant/routes.ts)、[上下文与预算](../packages/assistant/model.ts)。
- [商品接口](../packages/catalog/index.ts)、[评论接口](../packages/connections/reviews.ts)、[Amazon 接口](../packages/amazon/routes.ts)。
- [研究任务](../packages/operations/jobs.ts)、[费用与步骤执行](../packages/operations/execution.ts)、[后台工作流](../apps/jobs/src/index.ts)。

调查中确认的具体缺口：

1. 查库结果主要是文字，没有供下一步使用的商品 ID 和完整结构。
2. 助手不知道当前列表筛选条件、选中商品和当前任务，只能取得页面名和少量当前商品资料。
3. 对话历史不等于完整的调查记录，缺少目标、工具步骤、证据引用和恢复位置。
4. 助手创建的 discovery 任务将 AI 额度设为 0，不能直接当成完整自主研究入口。
5. 现有研究可能自动把商品加入观察池；助手必须明确区分分析与修改业务记录。
6. 评论总结存在直接模型调用路径；开放自动更新前，需要纳入统一 AI 预算与费用记录。
7. 多个研究任务加上助手思考的总消耗，需要受同一次调查额度约束。

## 4. 参考 Super Agent 的哪些设计

| 参考设计 | 在 HTCERP 中怎么用 |
| --- | --- |
| 一项工作有独立工作项 | 一次调查有独立目标、负责人、状态、步骤和结果 |
| 接待分派与具体执行分开 | 对话接收目标，后台调查执行器调用业务工具 |
| 工作项记录授权范围 | 记录平台、站点、商品范围、允许操作和费用上限 |
| 后续消息跟随原工作项 | 追问、补查结果和人工意见回到原调查 |
| 执行过程可以恢复 | 保存已完成步骤，继续未完成部分 |
| 交付后回到原渠道 | 报告回到发起调查的对话，可查看商品和任务依据 |

不直接搬用它的 GitHub、飞书、命令执行、工作目录、PR 或多 Agent 调度。我们的执行器使用明确注册的电商业务工具。

参考仓库明确标注研究原型，文章中的部分设计尚未实现。参考它的任务组织方法，不承诺其所有能力已经成熟可用。

## 5. 分阶段执行

### 阶段 0：建立范围和实施文档

本次交付：本文、工程执行清单、README 入口及需求状态更新。

- [x] 确认使用现有技术栈，先不接入 Harness 运行时。
- [x] 记录现状、缺口、阶段依赖和验收条件。
- [x] 明确本轮只写文档，不开发、不部署、不消耗业务额度。

### 阶段 1：让助手读懂工作台已有资料

做什么：

- [x] 将商品查询、潜力新品、详情历史、已有评论、已有竞品和本人任务结果开放为读取工具。
- [x] 工具返回商品 ID、平台、站点、数据时间、实际筛选条件、分页及缺失项。
- [x] 对话带入当前筛选条件、选中商品和任务 ID；服务端重新校验这些参数。
- [x] 工具读取复用现有业务查询，继续执行当前权限和结果脱敏。
- [x] 固定指令保留零模型调用路径，普通自然语言查询仍按现有 AI 预算执行。

这一阶段暂不增加连续调查，也不调用供应商补数据。

验收：分别询问“这件商品的趋势怎么样”“已有差评说了什么”“已有竞品是什么”，每次能调用对应读取工具。回答明确资料时间和缺口；无资料不编造；不能读取别人的私有任务。把多类资料连续查齐的完整调查放在阶段 2 验收。

阶段结果：接口接通，单次读取有用，为下一阶段准备可靠数据。

### 阶段 2：让助手完成一次连续调查和报告

做什么：

- [x] 建立独立调查记录，关联原对话、目标、范围、策略版本和 AI 上限。
- [x] 在现有 Jobs Worker 增加助手工作流，保存每一步，再决定下一步。
- [x] 允许多次使用同一工具查看不同商品，允许根据结果修改调查顺序。
- [x] 设置步数、候选数量、时间和 AI 上限；检测无进展的重复查询。
- [x] 支持查看进度、暂停、取消、刷新和重新打开后的恢复。
- [x] 完成后将结构化报告写回原对话；额度不足也交付已查结果和剩余缺口。

阶段 2 交付时只读取已有业务资料，数据积分上限固定为 0；澄清以部分报告结束。阶段 3、4 随后增加原调查内补充及明确确认后的在线补查。AI 思考和总结仍消耗受限 AI 预算。

验收：用户给出目标后，助手能连续查看多款商品、说明比较依据、输出推荐与淘汰理由。没有足够合适商品时不凑满三款。关闭页面不会丢任务。

阶段结果：第一个完整可用版本。它已经能接目标、调查、总结和交付。

### 阶段 3：让助手在授权后补查，并跟进后台研究

做什么：

- [x] 增加可确认的补查计划，明确商品、接口动作、页数、研究数量、数据积分、AI 上限及是否修改观察池。
- [x] 确认一次后，在该范围内自动推进；扩大范围或额度时重新确认。
- [x] 接通在线发现、指定商品更新、研究任务、Amazon 补查及评论更新。
- [x] 将助手模型、评论总结和研究子任务的消耗统一关联到本次调查。
- [x] 子任务的额度分配在提交前原子记录，防止并发突破调查总额度。
- [x] 后台任务完成后读取其结果，再决定下一步；等待期间不调用模型轮询。
- [x] 区分只分析与写入观察池，保留既有人工意见。

验收：拒绝或未确认时不发生外部调用；连续确认不会重复提交；额度不足不发送请求；费用不明停止自动重发；部分任务失败也能交付已有证据。

阶段结果：助手能够自主组织一次完整的在线选品调查。

### 阶段 4：让助手能接追问、改条件和继续原任务

做什么：

- [x] 调查执行中接收用户补充，在步骤边界处理，保留消息归属。
- [x] “继续刚才的调查”关联原任务；新的无关目标建立新调查。
- [x] 更改条件生成范围版本，旧确认不能授权新范围。
- [x] 已交付任务可以依据新要求继续，保留旧报告和证据时间。
- [x] 完善多运营并发公平性、权限变更检查和任务恢复。
- [x] 进度仅在有意义变化时展示，等待和无变化不反复输出消息。

阶段 2 的基本暂停、取消和恢复不能推迟到这里。本阶段完善的是追问路由、条件变更和交付后的继续。

验收：调查中说“排除第二款，重点比较第一款和第三款”，后续执行按新条件开展；已经在途的费用如实落账；另一个账号不能修改或继续该调查。

阶段结果：从一次性调查，升级为能持续协作的研究员。

### 阶段 5：积累团队认可的选品方法

做什么：

- [ ] 将已有潜力新品、趋势、竞品比较、标品与 POD 分析规则整理为有版本的业务说明。
- [ ] 汇总人工采纳、否决和修改的理由，建立固定评估样本。
- [ ] 每次变更调查方法，用相同样本比较报告质量、有效工具调用和费用。
- [ ] 根据已验证的收益再决定是否增加特定研究角色或规则触发的主动任务。

人工反馈先记录、复核，再更新规则。模型不能自行修改权限、预算或团队选品准则。

验收：同一组样本上能说明规则变更带来的具体差异，并能回退旧版本。主动任务和外部通知如需启用，另行确定范围和授权。

阶段结果：业务经验能被稳定复用，而不是每次重新解释。

## 6. 每个阶段都要遵守的规则

### 权限

- 用户身份由服务端取得，模型参数不能指定操作者。
- 继承当前账号权限。当前 viewer 可以做预算内 AI 问答及已有数据分析，不能借助手提交在线业务任务或修改候选。
- 每次工具执行、后台续跑和报告读取均检查当前权限，不只检查任务创建时的角色。
- 公共市场缓存可按已有规则复用，个人对话、调查结果和私有业务数据按可见权限隔离。
- 模型可用的工具按角色过滤，服务端执行时再次校验。

### 费用

- 固定指令可以不调用模型；读取已有资料不新增供应商积分，但自然语言调查仍有 AI 费用。
- 整次调查、子任务和团队日预算同时生效，不因跨日或恢复而重置调查总额度。
- 发送前预留，结果确认后落账。费用不明保留预留，停止自动重发。
- 公共报价和目录查询即使不按数据积分计费，也受调用数量、队列和限速约束。
- 循环到达限制时停止并说明原因，不能用无限重试绕过限制。

### 证据和报告

- 数据缺失、明确零、过期、查询失败和查无结果分开表示。
- 历史模型报告属于已有分析，不自动当成当前原始事实。
- Amazon 普通报价、内部价格分层推测和已验证的 Haul 证据分开标识。
- 类目排名不能当销量；价格差不能直接当利润；低星评论样本不能外推全部买家比例。
- 来源数据、评论、商品文字中的指令不能改变调查授权。
- 报告可以建议人工跟进，不能将建议写成已经验证的市场结论。

## 7. 首版报告长什么样

每份报告固定包含：

1. 调查目标、实际筛选条件、资料截止时间和覆盖范围。
2. 查到多少候选、实际深入看了多少款。
3. 推荐继续研究的商品及逐件理由。
4. 淘汰或暂缓商品及原因。
5. 缺失、过期、失败和仍需人工核实的证据。
6. 关联商品与任务入口，以及本次费用和待核对费用。

具体事实必须能追到已保存记录；无法支持的结论降为假设或证据不足。

## 8. 暂不纳入本轮路线

- 全量接入 Harness 或部署 Super Agent 原型。
- 更换模型、任意执行代码、任意 SQL 或全网浏览。
- 自动刊登、下单、采购、改价和无授权修改候选结论。
- 多 Agent 并行、向量数据库、自动学习并修改业务规则。
- 尚未真实接通的店铺业绩。当前业绩接口仍有 pending 和模拟预览，不能当成真实经营数据。
- 尚未解决的 Haul 专区自动搜索。不能用普通 Amazon 搜索替代后声称已经查到 Haul。
- 对外发送飞书、邮件等通知，及未经明确配置的主动巡检。

## 9. 怎么开始实施

1. 从阶段 1 开始接已有读取工具，保留现有界面行为。
2. 用本地隔离测试核对数据、权限和工具结果，不消耗业务额度。
3. 完成阶段 2，在隔离环境验收一次完整调查；这是首个主要交付点。
4. 阶段 3 先用模拟上游验证，再准备明确范围和额度的真实小样验证。
5. 后续阶段按实际使用反馈推进，每完成一阶段更新本文的勾选项和验收记录。

本地开发和测试不等于生产上线。部署、启用预算和真实收费验证在执行时按当时授权办理；本文本身不启用这些动作。

## 11. 第一、第二阶段实施记录（2026-11-01）

已实现七种缓存读取工具、页面筛选/商品/任务上下文、独立 AssistantWorkflow、调查与步骤持久化、团队和调查双预算检查、暂停/继续/取消、已归档响应重放、原对话报告、证据/费用/覆盖范围显示。

当前调查只读取本人任务，即使管理员也不将其他成员任务带入调查；普通工具仍沿用原有管理员可见范围。没有接入 Harness 运行时，没有改变模型，也没有启用在线采集、自动观察池写入或第三阶段工具。

### 最直白的使用步骤

1. 打开运营助手，把调查目标写清楚，点击“开始调查（已有资料）”。
2. 缺资料时看“在线补查计划”：查什么、查几次、最多花多少、是否写观察池。合适就确认，不合适就拒绝或先补充条件；也能手动“制定补查计划”。
3. 确认后等它查资料和收研究结果。可以关闭页面，回来接着看；也可以暂停或取消。
4. 改要求就发“补充调查条件”，或在主输入框写“继续刚才……”。另一个目标用“开始调查”，会另开调查。旧报告在“查看历史报告”里。
