## 数据语义

用户已明确“以 API 为准”：补库按 SP-API 的 `fulfillableQuantity` / 报告的 `afn-fulfillable-quantity` 计算，不要求与 Seller Flex 页面一致，也不把总库存或预留量当成可售量。符合既定范围和资格的记录标记 `candidateEligible=true`、`stockAuthority=AMAZON_SP_API`。当前仍为联调，`executionEligible=false`，候选等待原因为 `SIMULATION_ONLY`；不再使用页面库存未核实作为限制。来源快照与真实执行任务分表保存。历史存储的 `FBA_REPORT_UNVERIFIED` 标签仅描述当时来源记录，不覆盖最新库存权威规则。

库存报告仅明确接收 `store=Low-Cost Store` 的 JIT/J1T；空 store 等不明确范围单独统计排除量，不能视为零库存或混入当前仓库。缺少 store 列、残缺文件、重复 SKU、未完成报告均不发布。来源时间保留报告创建时间，重新下载旧报告不算更新后的库存。

刊登报告 Inactive 无法独立区分售罄、关闭或禁售，因此保留 unknown，不当作可安全补货。新品日期保留有时区的 open-date 证据；后续新日期及资格持久化。

订单使用已接入的 AMAZON_HAUL 订单读取，首次回看 7 天，此后用有重叠的游标持续收集“出过单”正向证据。该窗口不是“只管 7 天内出单”的业务规则；窗口外的历史订单目前尚未完整回填，未找到记录的资格仍为 unknown，绝不推定从未出单。

每轮完整快照只在所有来源成功后发布。D1 保留当前及最近完整快照，分块清理旧行，持续保留运行元数据、资格证据和 R2 报告。离线时服务端继续巡查；模拟回执保存在插件本机，重连后幂等回传。

## 设备协议

管理员会话接口（仍受原有会话、管理员权限、同源写保护、限流保护）：

- `GET /api/inventory-sync`：设置、最新/完整巡查、设备状态。
- `POST /api/inventory-sync/settings`：`{enabled,intervalMinutes,mode:'READ_ONLY'}`。
- `POST /api/inventory-sync/scan`：检查到期并派发；尚未到期返回 null。
- `GET /api/inventory-sync/candidates`：首 20 条来源候选预览。
- `POST /api/inventory-sync/pair`：10 分钟有效的高熵一次性配对码。
- `POST /api/inventory-sync/test`、`/revoke`：`{deviceId}`。

设备专用接口只对本前缀单独鉴权，不放开其他 ERP 接口：

- `POST /api/inventory-device/pair`：`{code,name}`，返回设备 token 与服务端绑定范围。
- `POST /api/inventory-device/heartbeat`、`GET /work`、`POST /results`：Bearer token。
- 设备 token 仅存哈希；设备绑定当前卖家/美国站/A1C5，不接受客户端指定其他范围。
- 模拟回执必须包含任务 nonce、规范文件 SHA-256、有效行数和 `mode:'SIMULATION'`，匹配后状态为 PASSED。模拟成功不等于 Amazon 接收成功。
- 原设备被撤销且有未回传回执时，显式恢复操作会将旧回执与原设备身份归档，再允许重新配对。不会以新设备身份重传旧回执。
