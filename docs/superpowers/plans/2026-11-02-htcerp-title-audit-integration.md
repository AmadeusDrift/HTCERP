# 海天城 ERP · 美国站标题自查与在售巡检接入计划

版本 v0.3 接入评审稿，2026-11-02。建议首批覆盖当前已绑定的一个美国站卖家。运营只输入英文标题；商品类目保留作证据，不是输入项。交付包括上架前预检、已上架标题同步、旧标题复查、同一个运营待办。图案、包装、实物及授权文件只作为人工核查提示。本次交付为计划。

| 品牌及 IP 家族 | 550 个入口 | 包含消费品牌、作品、组织和部分艺名；有的只收录了品牌本名。 |

## 三、词库怎样发布及匹配

1. **离线导出。** 从 `current_pool` 取普通商标，从 `ip_subject / ip_alias / ip_relation / ip_review_rule / ip_evidence` 取明确的家族、别名、规则与出处。保留注册和 IP 两套标识。按词条导出多对多引用，特别保留 Loki、Tundra 等同名多义记录。发布清单包含数据日期、规则版本、条数、校验值。本轮商标日包止于 2026-08-31，叠加部分 11 月核验及 IP 资料，页面分别注明日期。
2. **R2 放不可变版本，D1 放业务状态。** R2 保存匹配索引、按需查阅的证据分片及发布清单。D1 保存当前生效版本、店铺配置、同步进度、标题、命中和处置。实测全部去重文字组成的纯文本 JSON 约 460 KB、gzip 约 187 KB；映射、证据与运行时内存另测。第一版可每个 Worker 实例按版本缓存一次匹配索引，按命中再读证据，避免逐标题查 3 万条记录。无需商业检测 API。
3. **发布顺序。** 先把新版本写入 R2，校验每个分片、引用和实际读取，再在 D1 原子切换当前版本。正在运行的巡检固定使用启动时的版本。失败继续用上一完整版本；无可用索引时显示“检查未完成”。回滚只切换版本指针，并为受影响标题登记复查。
4. **统一匹配器。** API 和 Jobs 使用同一 TypeScript 模块，保留原字符位置用于高亮。用同一套测试向量校验离线导出和运行时的大小写、撇号、连字符、词界及显式别名。RedBull、HelloKitty、Spiderman 按已录变体命中；Red Bulletin 不命中 Red Bull。保留完整词组、同名各主体和对应依据。优先显示具体名称，普通短词仍可展开查看。
5. **给运营可执行的结果。** 明确知名角色及品牌用法显示“重点核权”；普通词、同名对象及真实兼容声明提示具体核查点。例如 Apple Slicer 检查普通词语境，Compatible with iPhone 检查适配型号、产品实际品牌和表达位置。若存在同店、同 SKU、同用途且未过期的授权记录，显示依据并降低待办优先级；规则变化或授权过期后重新打开。没有命中时显示“本版本未命中”。商标含义仍不清楚时允许转人工。

## 四、运营实际怎样使用

**入口 A · 新标题自查。** 在 ERP 粘贴英文标题、点击检查，即使没有 SKU 也可使用。返回原文高亮、品牌或 IP 家族、命中写法、核查原因、证据链接和词库版本。改完可以立即重查。此入口不调用 Amazon，可以先于店铺授权验证独立验收。建议登录用户可查，运营可处理待办，管理员可配置店铺、规则和授权。检查接口虽为 POST，属于只读计算，需要在现有角色映射中明确定义。

**入口 B · 在售巡检。** 运营可按店铺查看“正在同步／最后完成时间、应扫／已扫／缺标题／失败、优先核权待办”。每行展示 SKU、ASIN、标题来源、命中片段、本次提醒原因、证据和负责人。支持按品牌词查看所有相关 SKU。处置包括核实授权、记录误报及用途、已提交整改、转法务；只有重新读取确认商品标题及风险已变化后，才能显示整改完成。手工启动、自动启动进入同一队列和同一去重流程。

| 时机 | 读取及处理方式 |
|---|---|
| 首次接店、每日对账 | 按单一美国市场主动请求 Active Listings Report（`GET_MERCHANT_LISTINGS_DATA`）。异步等待报告状态、按 documentId 获取下载地址、按声明解压、流式解析 TSV。用列名识别 SKU、ASIN 和 item-name，处理 BOM、空值与表头差异。报告缓存可能造成延迟，分别记录源快照与抓取时间。报告失败、缺列或数量异常时保留上一版底册；有效空店须核实。 |
| 每 30 分钟 | 使用 `searchListingsItems` 的固定更新时间窗、重叠边界和分页，取得新上架、改名及状态变化；全部页成功后才推进游标。遇 1,000 条分页上限先切细时间窗，同一时间戳仍超限则标记缺口并用完整报告补齐。变更流不能覆盖的退出在售 SKU，由完整对账确认。 |
| 新规则、新词、授权变化 | 新词即使过去从未命中过，也必须从**全店在售标题**找到相关商品。单店试点直接分批重扫本地标题快照，避免错过新别名；只读 D1 与当前词库，免去重复请求 Amazon。授权变化可按店铺和 SKU 定向重查。 |
| 每周兜底 | 对所有在售 SKU 用最新版本重扫，覆盖未改名的老商品。报告、增量和周扫分别记录覆盖情况。高优先级且来源有争议时，再读卖家提交的 item_name 与目录标题并列展示。 |

Cloudflare Cron 使用 UTC。建议每半小时派发到期任务，D1 按北京时间计算每日和每周唯一执行窗口，错过一次在下一次触发补跑。外部源的可见延迟、队列等待和本系统处理时间分开记录。[Amazon 库存报告](https://developer-docs.amazon/sp-api/docs/report-type-values-inventory) · [Amazon Listings Items](https://developer-docs.amazon/sp-api/docs/listings-items-api) · [Cloudflare Cron](https://developers.cloudflare.com/workers/configuration/cron-triggers/) · [Workflow 等待与重试](https://developers.cloudflare.com/workflows/build/sleeping-and-retrying/)

## 五、数据、接口和故障处理

| 新增 D1 记录 | 主键或主要约束 |
|---|---|
| 词库发布清单 | 版本号唯一，保存校验值、各源截至日期、激活时间、回退版本。 |
| 店铺与运行配置 | 店铺＋市场唯一；存凭证引用、已验证 Seller ID、启用开关、时区与增量游标。 |
| 在售清单和标题快照 | 店铺＋市场＋SKU 唯一，ASIN 只是关联字段。保留标题哈希、原文、来源、观测时间、最近一次全量报告标记。发生风险时固定保留对应标题快照。 |
| 巡检运行、分片进度 | 店铺＋任务类型＋计划窗口＋词库版本唯一；存报告 ID、Workflow ID、租约、游标、各项计数及失败原因。 |
| 命中、工单、授权例外 | 命中可追溯到关键词、主体或注册和规则版本；按店铺＋SKU＋风险主体／规则合并未处理工单。同一标题重复扫描仅更新时间，实质性证据变化重新开启并留痕。授权记录带范围、到期日、复核人。 |

首版 API 建议使用 `POST /api/title-audit/preview`、`POST /api/title-audit/runs`、`GET /api/title-audit/runs`、`GET /api/title-audit/findings`、`POST /api/title-audit/findings/:id/resolve`。配置、发布词库及授权维护限管理员。所有 SKU 和证据查询按当前账户可见店铺过滤，下载签名 URL、令牌及授权文件不进入客户端日志或公开 R2。

Workflow 以“创建报告、等待、下载并分片、检查、发布结果”设置检查点。429 尊重 Retry-After，5xx 退避，凭证或角色错误标明需要管理员处理。下载 URL 过期重新取 documentId 的地址。报告取消或致命失败要显示原因，不能当成零命中。按批幂等写入，所有批次对账成功后再发布完成状态；旧报告不得覆盖更新的标题。部署或触发器重复投递应只产生一轮有效待办。设置单店并发上限及临时文件保留期，记录 D1/R2 用量用于核算成本。

## 六、执行顺序与上线验收

假设一名熟悉该项目的工程师、单个美国店铺、授权与测试环境可用。以下是估算；线上权限和真实报告生成时间尚未实测。

| 顺序 | 可交付结果 | 通过条件 |
|---|---|---|
| 第 1 天 | v0.3 导出器、版本清单及共享匹配模块；并行做试点店铺权限探测 | 34,478 个写法和所有主体引用核对成功；可读取真实报告和增量页，记录条数与时间。失败项有准确提示。 |
| 第 2 天 | ERP 标题检查页、只读 API、版本及证据展示 | 既有 16 个匹配用例在 Worker 实现中通过，补测普通词、同名、权限、无可用索引、Unicode 原文高亮。100 次代表性检查分别记录冷热耗时，热缓存 P95 目标 ≤2 秒。 |
| 第 3–4 天 | 全量首扫、半小时增量、定时回扫、失败恢复 | 首店清单与 Seller Central 同时段报告按 SKU 对账；缺失与失败单列。用模拟 1 万条压测，词库已就绪时内部全扫目标 ≤1 小时。验证限流、分页超限、中断重启及重复投递；无重复告警。 |
| 第 5 天 | 待办处置、回读确认、单店试点发布 | 验证“未知别名加入→未改标题重新报警”“授权到期→旧 SKU 重新打开”“修改标题→Amazon 回读→关闭”。执行类型检查、Vitest、Playwright 及两个 Worker dry-run；数据迁移、上传未激活版本、部署 Jobs 与 API、冒烟测试，最后开单店开关及 Cron。 |

建议灰度退出条件：完成一次真实全量、至少两轮增量、一次版本更新回扫，人工抽查重点命中与随机未命中标题，分别记录漏报和误报。问题出现时可停单店巡检、回滚词库，保留已生成记录。此版自查与巡检均为 Amazon 只读；真实下架案例后续可作为独立证据接入。上线汇报只列版本、实际覆盖 SKU、需处理数、失败数和最后成功时间。
