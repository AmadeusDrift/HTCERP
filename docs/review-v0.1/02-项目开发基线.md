# 自动选品工作台：项目开发基线

v0.1｜2026-10-31｜待用户确认。约束后续工程，不代表已实现。

## 1. 仓库与模块依赖

**长期验收要求（2026-10-31 确认）**　所有涉及用户操作的新增功能与优化，都要针对以下设备调整显示和交互，并通过受影响的主要操作流程。

| 参考设备 | 验收重点 |
| --- | --- |
| 三星 Galaxy S26 Ultra、iPhone 18 Pro Max | 首屏优先呈现数据，检查可读性、单手触控、操作反馈、弹层和返回位置。 |
| 三星 Galaxy Z Fold 8 Ultra 系列 | 折叠外屏与展开内屏分别验收，并在操作中展开、折回，核对筛选条件、选中项和阅读位置。 |
| 16、24、27 英寸 PC 屏幕 | 分别检查常用系统缩放下的首屏高度、字号、表格列宽、侧栏、弹窗，以及键盘与鼠标操作。宽屏用来并排比较数据，窄窗口也能完成主要操作。 |

布局按浏览器可用宽高自适应。验收记录注明设备或模拟环境、实际浏览器视口和缩放，区分真机结果与模拟结果。屏幕对角线用于选择参考设备，不能单独推算浏览器可用空间。

建议工程位于 workbench/，现有探测脚本、原始数据与 .env 保持原位；不要将整个父目录作为前端静态资源上传。工程生成前检查已有文件和 AGENTS.md，避免覆盖。

```text
workbench/
  apps/web/                 页面、路由、视图状态
  apps/api/                 Hono、鉴权、oRPC、接口装配
  apps/jobs/                Cron、Workflows、步骤执行
  packages/domain/          商品、观测、候选等纯领域类型
  packages/contracts/       边界输入输出、错误结构
  packages/modules/         discovery/catalog/research/tracking/candidates
  packages/adapters/        geekbi/amazon/openrouter/repositories
  packages/ui/              统一组件与设计 token
  packages/config/          共享工程配置
  migrations/               有序数据库变更
  tests/integration/        跨模块及 Worker 环境验证
  tests/e2e/                浏览器关键路径
  docs/                     架构决策、运行手册与接口说明
```

依赖方向：apps → modules → domain/contracts；adapters 实现 modules 定义的接口，在 apps 装配。domain 不导入页面、Cloudflare bindings 或供应商 SDK。禁止业务模块直接导入另一个模块的私有实现；跨模块通过公开应用服务调用。

## 2. 接口与版本

所有外部输入和供应商响应做运行时校验；oRPC 类型不能代替边界校验。列表必须服务端分页、筛选和排序，不一次向浏览器返回全部商品。金额带币种，时间存 UTC 并以北京时间显示，平台/站点不可省略。

统一错误包含 code、message、requestId、retryable、source；浏览器不得收到密钥、签名、原始堆栈。区分 INVALID_INPUT、UNAUTHORIZED、FORBIDDEN、SOURCE_AUTH、SOURCE_RATE_LIMIT、SOURCE_UNAVAILABLE、BUDGET_EXHAUSTED、DATA_INCOMPLETE。

step 契约：type、version、inputSchema、outputSchema、allowedSources、estimatedCost、idempotencyKey、retryPolicy。上下文包含 runId、stepId、strategyVersion、permissions、budgetReservationId、cancelSignal。结果为 success/partial/skipped/retryable_failure/permanent_failure，附 evidenceRefs、usage 和公开结果摘要。更改契约时增加版本并处理已有任务，不原地修改旧任务含义。

## 3. 状态、重试与幂等

run 状态：queued → running → succeeded/partial/failed；可进入 pausing/paused、cancelling/cancelled。暂停/取消先停止新外部调用，已在途请求允许结束并落账；恢复只继续未完成步骤。

每日调度按 strategyId+market+businessDate 取得唯一租约，防止重复触发。步骤幂等键含 runId+type+version+inputHash；相同成功步骤复用。用户要求强制刷新则新建观测和调用记录，不覆盖原证据。

至少一次投递/步骤重试不能保证外部 API 恰好一次扣费。发送前持久预留；成功确认扣费，明确未发送才释放，超时/断线保留 uncertain，重试也单独预留。供应商返回后保存证据与业务更新使用可恢复提交模式；失败时能从 R2 响应重放清洗，避免无谓重采。

本地和云端进程都必须防并发超额；预算预留使用事务/原子条件更新。按账户余额组记账，不能把同账户多 key 当多份余额。429 不通过换 key 规避；可恢复网络/5xx 最多三次带抖动退避，超过后 partial/failed 并允许人工补跑。非幂等外部动作不得自动套用该策略。

## 4. 数据与历史

唯一性：platform+market+externalProductId；规格有独立 ID。追加观测，当前快照是可重建的投影。原始来源值、标准化值、AI 派生值与人工值明确分层。

区分缺字段、明确零、估算值、区间值、过期值、采集失败和下架。首次搜不到标 not_observed；只有明确状态或额外核验证据才标下架。销量时间窗和时区必须随指标保存；商品价不能在未匹配规格/币种时与供货价算利润。

迁移文件按序、可审查，不改写已应用迁移；破坏性变更走“新增→回填→切换→验证→清理”。记录 schema version。上线前演练 D1 导出恢复及 R2 原始响应重放；备份频率和归档保留期在生产启用前确认，未配置时不能宣称长期恢复有保障。

## 5. 配置和安全

开发/预发布/生产三套独立 Cloudflare 资源与密钥；测试不默认扣生产积分。密钥由 Workers secrets 管理，不提交 Git、不写前端、不回显日志、不进入提示词或工件包。

Access JWT 校验 issuer、audience、签名与有效期；仅保护网页不足以保护 API。应用角色建议管理员、运营、只读：修改预算/密钥/策略需管理员，发起研究和反馈需运营或管理员，只读不能触发付费。手动入口做鉴权、请求大小限制、速率限制与重复提交保护。

模型可使用的工具是明确注册集合；不执行模型生成的任意代码/SQL，不让模型访问 secrets。外部内容中的指令不能更改角色和预算。图片/链接解析只允许必要的公开 HTTPS 来源，限制体积与超时，防止读取内网及元数据服务。

## 6. 工具链与升级

Node 24 用于本地工具链，生产是 Workers；pnpm 版本、依赖与兼容日期在工程创建时固定并保存锁文件。VibeStart/CLI 的历史组合验证不等于本项目测试通过。Wrangler 配置、数据库迁移和 Worker 环境下的测试是交付依据。

VibeStart 管辖项用 add/upgrade 与 dry-run 维护，业务模块不伪装成模板能力；每次升级记录模板版本、依赖变化和手工迁移项。生产依赖升级先预发布，验证关键流程和迁移后再发布；应用版本、任务协议、数据库版本分别记录。

代码默认 strict，禁止绕过类型检查掩盖供应商变化。共用配置及任务按生成工程实际 package.json 定义；使用 vp install、vp check 和实际存在的测试任务，不假定所有任务默认存在。当前文档阶段不安装 Vite+ 或项目依赖。

## 7. 必要测试与交付门槛

单元：缺失与零、指标口径、去重、预算原子预留、步骤幂等、模型返回校验。集成：Workers+D1/R2、任务中断恢复、限流、供应商失败、权限。模型测试用保存的非敏感 fixture 和标注样本，不以概率大小代替领域准确率。

端到端至少覆盖：登录→筛选真实商品→详情历史→创建研究→进度→保存候选→反馈；只读用户不能发起付费任务；刷新/关闭页面任务仍继续。明确区分真实 AI、测试 fixture、待配置状态，不伪造推荐或成功提示。

性能建议验收线（待批准）：普通列表 50 条、商品库至少 22,664 件、约定测试网络和索引后服务端列表 P95 ≤1秒；首个可操作页面 ≤3秒，至少 20 次测量，不以供应商/AI 等待计入列表性能。浏览器只加载当前页，图片懒加载。失败不允许静默显示旧数据为本日成功。

运行日志关联 runId/stepId/requestId、来源、耗时、状态和费用。对日任务未启动/未完成、预算暂停、来源鉴权失败提供任务中心可见状态。外发邮件/通知不是首期默认权限。
