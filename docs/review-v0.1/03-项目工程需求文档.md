# 自动选品工作台：项目工程需求文档

v0.1｜2026-10-31（北京时间）｜**提交评审，用户确认后才推进**。

## 1. 目的与成功定义

建立云端、每日自动更新、由 AI 驱动研究的美国站选品工作台。将跨平台商品数据逐步转成可追溯的产品方向、标品机会、差异化/POD 思路和跟进对象。经营判断由人员负责。

短期成功：主管能在真实数据页面上查看商品、研究证据、候选与反馈；业务流程可调整。系统成功不以“商品多”或“AI报告多”衡量，应能说明来源时间、判断理由、缺失信息和后续行动。暂不承诺销量预测或利润。

## 2. 事实、建议与未决项

已确认：美国站为主；两种入口与两条机会线；Cloudflare 托管/网页登录；极鲸云 API 每天自动发现与更新；OpenRouter Terra+Decisions；Amazon 优先 SP-API；已有非PII权限；现有数据作为基础；今天/首阶段优先可视化可操作页面，主管沟通后补规则。

实测起点：美国站扩大阶段 Temu 16,272、SHEIN 3,185、TikTok Shop 1,595、AliExpress 1,612，共 22,664 件。本次 Temu 98/98 详情样本返回历史；TikTok 18/40、AliExpress 6/40；样本偏向较高销量，不能外推平台覆盖率。SHEIN 仅测试搜索，未证实独立历史能力。此前小样本与本批有重合，初始化不得直接将计数相加。

建议：模块化单体、独立后台 Worker、官方 Wrangler 部署、D1/R2/Workflows、Access+应用角色。见 01、02；这些方案需用户本次确认。

未决项有明确上线约束：每日北京时间、日数据积分上限、AI金额上限、初始类目/排除品、每日研究规模、账号角色名单、历史保留期、域名与Cloudflare账号、OpenRouter凭据、Amazon账号/站点实际可调接口、Haul数据来源。分别在对应功能启用前确认；未确认预算和时刻时定时任务保持禁用，未接通来源显示待接入，不能伪造结果。

## 3. 角色与工作方式

管理员配置连接、规则、预算与人员；运营发起研究、筛选、收藏和反馈；只读人员查看结果。初期可由一人兼任，权限边界仍在后端生效。

批量模式：自然语言描述目标，配置市场、来源、类目/关键词、范围与预算，预览执行计划后运行。指定商品模式：名称、链接或图片进入搜索/识别，再进行单品和相关产品方向研究。API和AI未配置时允许浏览既有数据，明确提示哪些操作无法执行。

## 4. 功能需求与验收编号

| 编号 | 需求 | 核心验收 |
|---|---|---|
| F01 | 商品库及初始数据 | 幂等初始化22,664件样本，保留原站点、来源及供应商时间；重复执行不新增重复商品 |
| F02 | 服务端搜索与筛选 | 支持平台、关键词、类目、价格、日/周/月销量、更新时间、数据完整度；分页和排序可组合，缺字段单列 |
| F03 | 列表/图片视图 | 显示图片、标题、价格、需求指标、来源日期与候选状态；详情可直达；切视图不丢筛选 |
| F04 | 商品详情与历史 | 当前快照、规格、价格、销量、评分、评论、类目、店铺、来源证据；缺字段提示；历史缺日期不画成零 |
| F05 | 每日发现与更新 | 云端每日一轮，新品与关注对象更新分开；有租约、分页、去重、预算、进度与运行摘要；关闭页面仍运行 |
| F06 | 手动研究任务 | 自然语言和指定商品两入口；支持范围及预算；禁止用户仅凭任意URL要求后端访问内网 |
| F07 | AI 判断与研究 | Terra提出研究动作并写报告，Decisions做结构化判断；执行受权限预算约束，来源内容不覆盖规则 |
| F08 | 研究详情 | 展示产品方向、同类集合、趋势、标品/POD思路、缺失及建议，关联输入快照和证据；不冒称已核验利润 |
| F09 | 候选与观察池 | 支持候选、观察、跟进、暂缓、不适合；标品/POD可同时选；反馈原因与作者、时间保留 |
| F10 | 任务中心 | 状态、步骤、费用、异常、暂停/恢复/取消与补跑；刷新页面从后台恢复状态；成功步骤不重复扣费 |
| F11 | 数据与模型设置 | 后端密钥、来源状态、模型ID、预算、策略/提示词版本；不向前端返回密钥；同余额多key只记一份资金 |
| F12 | 网页登录与权限 | 未认证拒绝API；只读不能发起费用；修改连接与预算仅管理员；记录重要变更 |
| F13 | Amazon比较 | 优先SP-API；真实账号验证可调字段；不足信息标记缺失；不承诺取得任意竞品真实销量 |
| F14 | Haul与后续来源 | 预留来源/比较能力，不将常规商城低价当Haul；当前缺来源时显示未接入，启用前单独验收 |

## 5. 页面与信息架构

发现商品：顶部任务入口和筛选，中心商品表格/图片，右侧详情或研究抽屉；原始事实与AI判断视觉区分。

AI研究台：任务描述、选择对象、范围与预算、执行计划、进度、公开行动记录与报告。

详情页：概览、历史、相关产品、AI分析、证据、人工反馈。跨平台“同款”带匹配置信/证据与确认状态，不仅凭主图类似直接合并。

候选/观察池：产品方向分组、机会类型、跟进状态、人员意见。任务中心：每日轮次、手动任务、费用与异常。设置：数据连接、模型、策略、权限。

视觉建议：浅灰白底、深蓝导航、青色操作强调；适配笔记本及桌面宽度、键盘操作、加载/空状态/失败状态。图表可查看数值与来源日期，不以大数字装饰替代操作。

## 6. 首期与后续边界

M1 页面与基础库：可操作发现页、筛选、详情历史、候选反馈、任务与设置页面；用真实缓存初始化，未实现动作明确标待接入。M1本身不代表每日自动化验收完成。

M2 云端接入与任务：极鲸云在线查询、每日发现/更新、预算与恢复、Access登录和发布验证。

M3 AI闭环：OpenRouter双适配真实调用、小范围研究、证据报告与反馈，验证权限预算及成本。

M4 Amazon与规则深化：SP-API账号验证、可用数据比较；与主管确认策略后扩展研究和机会判断。Haul来源有证据后独立加入。

产品MVP整体要求M1—M3通过；M4可后续，但在正式跨平台比较交付前必须完成对应接入与验收。批准文档后可交错实现必要后台以支撑页面；不以“只读展示”替代自动化目标。以上为顺序与交付范围，不是工期承诺。

当前不包含自动采购/刊登/改价/广告执行、图片生产工作流、桌面exe、移动App、通用拖拽编排、任意插件市场。后续按独立需求扩展。

## 7. 关键场景验收

AC01：相同初始化执行两次，平台+站点+商品ID唯一，来源时间未改成执行当日。
AC02：筛选后切视图、翻页、打开详情能保持上下文，缺失销量与0值分开。
AC03：同一天调度重复触发只产生一个有效轮次；关闭网页后仍在云端推进。
AC04：某页超时或429，预算和错误可见；没有将失败写成零；恢复不重取已成功页，不换key绕限流。
AC05：在最后一笔余额有并发请求时不会超过授权预算；不确定扣费记录保留。
AC06：修改策略后新任务使用新版本，运行中与历史任务仍可追溯旧版本。
AC07：同一输入真实Terra研究和Decisions分流均可追溯；没有凭空填写Amazon销量/供货成本；未配置时显示待配置。
AC08：低证据建议进入观察/复核；人工反馈持久化并可查看，但不宣称系统已经完成训练。
AC09：未登录/只读用户不能触发付费请求；访问日志与打包内容无密钥。
AC10：迁移在预发布跑通；失败可回滚应用且有数据恢复方案；部署后测试定时入口与手动入口。
AC11：每天摘要说明新增数、更新数、覆盖范围、异常和费用，不把部分成功显示成完整成功。
AC12：Amazon接入后按账号与站点核对实际返回字段；Haul未接入时不会展示虚构比较。

## 8. 成本与运行策略

供应商积分与模型费用分别记账，保存授权上限、预留、确认和不确定消耗；API产品/模型定价以实际响应和账单核对。每日任务启用前提供可审查的调用量估算，不默认每天逐件查全部商品详情，也不默认把全部商品送入Terra。

免费测试key不构成长期生产方案；付费账户和余额组在生产前明确。只支持已授权连接，不通过轮换凭据绕过上游限制。用户当前授权的文档工作不包含充值、付费调用或创建云资源。
